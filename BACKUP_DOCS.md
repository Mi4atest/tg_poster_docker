# Резервное копирование базы данных

Резервное копирование выполняется **внутри приложения** (Python), без хостового
cron, и настраивается прямо в боте.

## Где настраивается

Бот → «⚙️ Настройки → 💾 Резервное копирование»:

- **Токен бота бэкапа** — отдельный Telegram-бот для отправки архивов (хранится
  зашифрованным в БД, ключ — `MASTER_KEY`).
- **Chat ID** — куда отправлять архивы (например, приватный канал/чат).
- **Имя проекта** — используется в имени файла бэкапа.
- **Автобэкап (вкл/выкл)** и **время запуска** (ЧЧ:ММ).
- **Медиа в бэкап** — дополнительно архивировать каталог `media/`.
- **«📦 Сделать бэкап сейчас»** — ручной запуск.

## Как это работает

- Планировщик (`app/services/backup_service.py`, цикл `backup_scheduler_loop`)
  раз в сутки в заданное время запускает бэкап, если он включён.
- Дамп БД создаётся через `pg_dump` (пакет `postgresql-client` встроен в образ),
  сжимается gzip и отправляется в Telegram.
- Архивы складываются в `backups/` (смонтировано на хост). Копии старше
  `keep_days` (по умолчанию 30) удаляются.

## Восстановление

```bash
bash scripts/restore.sh путь/к/файлу/резервной_копии.sql.gz
# без аргумента берётся самый свежий бэкап из backups/
```

> ВНИМАНИЕ: восстановление перезаписывает текущую базу.

## Миграция со старой схемы (cron + .env)

Раньше бэкап настраивался через `setup_backup.sh` и переменные `BACKUP_*` в `.env`.
Теперь эти значения при первом старте автоматически импортируются в БД (bootstrap),
а токен — в зашифрованное хранилище. После проверки в боте строки `BACKUP_*` из
`.env` можно удалить. Старое cron-задание (если было) можно убрать: `crontab -e`.
